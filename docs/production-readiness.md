# 生产就绪评估与上线门槛

评估日期：2026-10-25。目标机器按最新反馈记录为 **64 核 / 256 GB 内存 / 512 GB 系统盘 / 4096 GB 数据盘**，学生规模 500 人以上。尚未连接或验证目标服务器；CPU 架构、CPU/磁盘型号、数据盘挂载位置、网络和预计同时提交人数仍待确认。

结论：当前版本可在隔离、受控、只运行可信样例的环境做功能验证和容量压测，**不能直接作为面向不可信学生代码的公网生产服务**。硬件容量不能替代安全隔离、认证加固或架构优化。

## 阻断项

| 优先级 | 现状 / 证据 | 上线前要完成什么 |
| --- | --- | --- |

| P0 | `sandbox: null`；学生程序共享 Worker 的网络、文件系统和身份 | 每任务隔离、最小文件挂载、禁止访问内部数据库/队列/API 凭据、网络策略、资源限额和恶意样例回归；评估将测评节点与控制面分离 |
| P0 | 演示口令和会话密钥写在 Compose/模板里 | 正式部署使用独立强凭据和受控注入；修改真实账户和客户端配置，验证轮换。不要把已初始化的数据卷删除来换密码 |
| P0 | Node 16、MongoDB 4.4 已结束官方支持 | 先做 Node/依赖兼容升级，再做有备份、有回退方案的 MongoDB 分步迁移；不要直接替换现有数据库大版本镜像启动旧卷 |
| P0 | HTTP 绝对 URL、`ws://` CSP、默认 session cookie 配置未完成 HTTPS 适配验证 | 配置正确的公开 Origin、反代信任边界、HTTPS、WSS、Secure Cookie、CSRF 和重定向验证；不能只加一层 Nginx 就宣称完成 |
| P1 | 无目标服务器备份恢复、故障恢复和容量验收记录 | 验证 Mongo/GridFS、Redis 配额、队列和任务表的一致性恢复；演练停机/重启，记录 RPO/RTO |
| P1 | 全量两两比赛 O(N²)，默认投递/测评参数面向本机 | 测量投递速率、排队时间和回合吞吐，明确赛制和可接受排空时间；必要时经业务确认改成分组/抽样等赛制 |

官方生命周期依据：[Node.js EOL](https://nodejs.org/en/about/eol)、[MongoDB 生命周期](https://www.mongodb.com/legal/support-policy/lifecycles)。这里不把某个新版本号当成已验证升级目标；升级方案需要另外评估和测试。

## 本轮已准备和已做的小幅保护

- `deploy/compose.staging.yaml`：独立项目、网络、端口和数据目录；不与本地默认栈合并，也不是生产模板。
- `scripts/deployment-preflight.js`：静态核对端口、权限、资源、演示凭据及生产阻断项；输出不包含 Compose 的密码和连接串。
- `scripts/load-test.js`：分级闭环 HTTP 负载、预登录后的并发提交、最终状态轮询、错误/延迟报告；远程和写入均需明确确认。
- `scripts/capacity-plan.js`：500 人首次提交/已有历史提交两种任务数量和耗时、存储假设估算。
- `scripts/collect-load-metrics.js`：项目容器 CPU/内存/块设备 I/O 和 RabbitMQ ready/unacked/consumer 快照。
- `scripts/seed-load-accounts.js`：仅创建独立前缀、随机密码的测试账户，自动完成测试账户的首次登录状态；不修改已有账户，不自动清库。
- 删除 MongoDB 连接串和 Redis 密码的明文日志输出；给 Portal / Worker 的文件日志增加轮转。历史日志不会被本轮自动清理，仍需审查已有泄露风险。

没有在本轮擅自修改密码存储、替换数据库版本、改赛制、提高默认 Worker 并行数、部署服务器或发起真实应用压力测试。

## 预检怎么用

需要本机有 Node.js 和 Docker Compose 命令；解析配置不要求 Docker 引擎运行：

```bash
node scripts/deployment-preflight.js --mode production
```

当前生产预检应返回非零退出码（1）：这些阻断项确实尚未解决。退出码 2 表示配置无法检查，不是安全通过。不要通过修改检查结果或忽略退出码来满足上线流程。

staging 预检见压测手册。staging 的 `passed: true` 仅说明基础静态保护满足测试要求，生产问题仍作为 warning 输出；它不是“可公网运行”的结论。备份恢复与隔离验证为人工门槛，不能仅靠 grep/静态配置自动认证。

## 上线验收证据

至少保留：代码提交 SHA、镜像版本/摘要、脱敏配置、机器架构及磁盘信息、压测参数、测试数据规模、HTTP 错误/P95/P99、有效提交比例、测评排空时间、队列峰值和变化、CPU/内存/OOM/磁盘曲线、重启恢复过程、备份恢复结果。

安全检查与容量验收分开签收：网页 500 并发成功，不代表 500 份学生程序可安全运行，也不代表后台能在规定时间完成全部比赛。
